## 这是什么

CFTunnel 是 [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/)（`cloudflared`）的桌面图形客户端。它替你做完这些事：

- 下载 / 更新 `cloudflared`
- 走一次浏览器授权登录，拿到本机的操作凭证
- 创建与启动隧道（临时域名 / 固定域名）
- 在软件里直接编辑 **云端的 ingress 路由**，不用打开 Cloudflare 后台
- 查询、改名、解绑 DNS 路由
- 给某个域名加一把 **访问密码锁**（Cloudflare Access + Service Token），没有凭据的连接一律 403
- 在另一台机器上做客户端，把远程服务映射到本地端口

一句话：**本地服务 → 公网可用**，全程不碰命令行、不碰 `config.yml`。

> 🌐 **想先看界面再决定装不装**：`main` 分支每次推送都会把前端编译成静态网页发布到 GitHub Pages（浏览器里自动进入**演示模式**，用内存里的假数据把全部交互跑通，不碰任何真实账号与云端资源）：
>
> **在线演示：<http://cftunnel.520jacky.dpdns.org/>**（GitHub Pages 站点，已绑定自定义域名；默认的 `bayueqi.github.io/ZQ-CFTunnel/` 会跳到这里）

## 快速开始

四步走完，前两步在软件里点，后两步就是正常的填表：

| 步骤 | 在哪 | 做什么 |
| :--- | :--- | :--- |
| **1. 装 cloudflared** | 侧边栏 **⚙️ 配置** → 「📦 安装 cloudflared」 | 自动识别系统与 CPU 架构，从官方 Release 下载到软件目录 |
| **2. 授权登录** | 同一个卡片 → 「🔑 Cloudflared 授权登录」 | 唤起浏览器，选中你要授权的域名，证书落到 `%USERPROFILE%\.cloudflared\cert.pem` |
| **3. 建隧道** | 侧边栏 **🖥️ 服务端** → 固定隧道 / 临时隧道 → 「＋ 创建」 | 选协议、填本机端口（要长期固定域名就再填域名） |
| **4. 启动** | 列表行尾 **▶** | 隧道跑起来；临时隧道会给你一个 `*.trycloudflare.com` 域名，固定隧道用你绑定的域名 |

> ⚠️ **只有固定隧道需要第 1、2 步**。临时隧道免登录、免凭证，装好 cloudflared 就能用。

**开始之前你需要：**

1. 一个 Cloudflare 账号（[注册](https://dash.cloudflare.com/sign-up)）；
2. 一个托管在 Cloudflare 上的域名（用固定隧道时必需，DNS 由 Cloudflare 接管）；
3. 本机能跑 `cloudflared`（软件可以帮你装）。

## 两种隧道：怎么选

软件里的隧道分两类，本质区别是 **「配置写在哪、域名怎么来」**：

| 对比维度 | ⚡ 临时隧道 | 🟢 固定隧道 |
| :--- | :--- | :--- |
| **配置写在哪** | 无配置，纯命令行临时起 | Cloudflare 云端 ingress（软件里可视化编辑） |
| **域名来源** | Cloudflare 随机分配 `xxx.trycloudflare.com` | 你自己域名下的某个子域名 |
| **需要授权登录** | ❌ 不需要 | ✅ 需要 |
| **域名是否固定** | ❌ 每次启动都变，进程停了就失效 | ✅ 固定，随时可重连 |
| **能否多开** | ✅ 可同时开多条 | ✅ 可同时运行多条 |
| **能否上密码锁** | ❌ 域名不归你账号，加不了 | ✅ 每个域名可单独上锁 |
| **凭证位置** | 无 | `%USERPROFILE%\.cloudflared\<隧道ID>.json` |
| **启动命令** | `cloudflared tunnel --url <协议>://127.0.0.1:<端口>` | `cloudflared tunnel run <名称>`（配置取自云端） |
| **适用场景** | 临时分享、快速验证连通性 | 长期对外发布本地服务 |

> 💡 **一句话判断**：只想临时拿个链接给别人看 → **临时隧道**；要长期固定域名 → **固定隧道**。

> 📌 **固定隧道建好即为「云端托管」**：软件写入云端 ingress 的同时，会把这条隧道的配置源切到 Cloudflare。
> 早期版本里那个独立的「云端托管」视图**已并入固定隧道** —— 一条隧道是不是云端托管只是它的属性，不该让它同时出现在两个列表里。

## 临时隧道

**最省事的发布方式**：免登录、免凭证、免绑定域名，填个端口就能拿到域名。

1. 侧边栏 **🖥️ 服务端 → ⚡ 临时隧道**；
2. 右上角 **「＋ 创建」** → 选协议 + 填本机端口（选 UNIX / UNIX+TLS 改填套接字路径；选 Hello World 不显示地址栏）→ 点 **「生成」**；
3. 稍候拿到形如 `https://xxx.trycloudflare.com` 的临时域名；
4. 列表里每条显示**目标地址**与**临时域名**（**点域名即复制**），行尾有 **「🌐 打开」** 与 **「⏹ 停止」**；
5. 右上角 **「🔄 刷新」** 与后端对账真实运行状态，状态胶囊显示 **「运行中 (N)」**；点「停止」会先弹二次确认。

> ⚠️ 临时域名**每次启动随机变化、进程停止即失效**，只适合临时测试与快速分享。
> TCP / SSH / RDP 等服务同样可以走临时域名（与固定隧道行为一致）。

## 固定隧道

协议、端口、域名都在软件里改，保存即写云端、立即生效；**支持多开**（多条隧道可同时运行）。

> 📌 **一条固定隧道 = Cloudflare 云端的一组路由**。配置全部住在云端 ingress，本机不存 `config.yml`。
> 软件额外在本机记一份「隧道名 → 源站协议 / 端口」的小抄，只为让列表行内的 ▶ 不必先打一次网络请求 ——
> 真正生效的永远是云端配置。

### 隧道列表

| 列 / 按钮 | 说明 |
| :--- | :--- |
| **隧道 ID** | 唯一标识（悬停看全；点击该行即选中） |
| **隧道名称** | 创建时填的名字（**纯英文字母**），创建后不可改 |
| **创建时间** | Cloudflare 侧记录 |
| **绑定域名** | 该隧道已绑定的域名，**点域名即复制**；没绑定显示「未绑定」 |
| **连接状态** | Cloudflare 边缘当前的活动连接数，无连接显示 `-` |
| **状态** | 绿点「运行中」/ 灰点「未运行」 |
| **行尾 ▶ / ⏹** | 启动 / 停止**这一条**，按钮随状态自动切换 |
| **行尾 ✎** | 打开**修改**弹窗（与创建同一界面，见下节） |
| **行尾 🗑** | 删除（二次确认）。走**强制删除**：即使仍在运行、云端还有活动连接也会删掉，本机在跑的会先停进程；该隧道绑定的域名与密码锁会一并清理 |
| **右上角 ＋ 创建** | 新建隧道 |
| **右上角 🔄** | 重新拉取列表并同步运行状态（进程意外退出也能对账回来） |
| **状态胶囊** | 显示 **「运行中 (N)」** |

> 📌 **列表就是账号下的全部隧道**，不再按「本机有没有凭据文件」拆成两个 —— 那个判定跟「是不是云端托管」是两回事。

> 💡 **多开时每行的 ▶ 用哪份配置**：隧道对象本身不保存源站协议与端口（Cloudflare 侧只存隧道），所以 CFTunnel 在创建 / 修改时会把「隧道名 → 协议 / 端口」记到本机，行内 ▶ 据此直接启动。
> 若某条隧道**没有保存记录**，点 ▶ 会引导你先点「修改」补全，**绝不会拿别的隧道的端口去硬启动**。

### 创建 / 修改隧道

**创建与修改共用同一个弹窗** —— 一条固定隧道的内容都在云端 ingress 里，「建一条」和「改一条」填的是同一批东西。差别只有三点：

| | 创建 | 修改 |
| :--- | :--- | :--- |
| 标题 | 「创建固定隧道」 | 「修改隧道」 |
| 隧道名 | 可填写（纯英文字母） | **只读**（隧道名就是凭据文件名，改名要连带搬凭据、清旧锁，代价远大于收益） |
| 打开时 | 空白表单（只有一条兜底行） | 先读回云端已有配置再回填 |

弹窗里的三块，与 Cloudflare 后台的 Tunnel 详情页一一对应。

#### ① 已发布应用程序路由（= 云端 ingress）

一行一条规则，**你只选协议、填端口、填域名，`service` 字符串由程序拼**：

```
[协议 ▾]   [本地端口]   [域名]                  🗑
 HTTP       8080         mc.example.com
```

- **协议**：九种服务类型任选（见[支持的全部协议](#支持的全部协议)）；
- **本地端口**：选 UNIX / UNIX+TLS 时这格变成**套接字路径**，选 Hello World 时整格隐藏；
- **域名**：这条规则要匹配的 hostname，**可以留空**；
- **其他（原始值）**：反解不出协议与端口的存量规则会落到这一档，此时显示原始 `service` 输入框，**原样保留、不会被改坏**。

**域名留空 = 这一行不写进云端**。保存时会**整行跳过**（并在控制台记一行日志说明），既不报错、也不影响其它行 ——
Cloudflare 只允许**一条**不带 hostname 的规则，而且必须在最后，那条永远由兜底行担任。
所以「没填域名的普通行」没有任何存在意义，保留它只是给你一个不用立刻删掉的缓冲。

**末尾兜底行（常驻）**：

```
[默认兜底]
 [协议 ▾]  [本地端口]
  未匹配任何域名的请求会走这一条     http_status:404
```

- 它**永远在列表最后、永远渲染、永远写进云端**，不因为上面的行填成什么样而消失或变形；
- 默认档是 **`http_status:404`**（未匹配就回 404）。把协议换成具体服务再填上端口，未匹配的请求就会**转到那个本地端口**（单域名隧道常用这种「反正都给我」的写法）；
- 它没有域名输入框、也没有删除按钮 —— 「不带域名」和「排在最后」是它的定义，不是可选项；
- 云端本来就有的无域名规则会**原样读回**：`http_status:404` 显示为「未匹配回 404」，其它状态码落到「其他（原始值）」原文保留。

**校验规则**（点过保存后才标红）：端口需为 1–65535、域名格式需合法、同一域名不能出现在两条路由里。
**域名留空的行不参与校验** —— 它本来就不会被写出去，没必要拦你。

#### ② 主机名路由

用于 WARP 私有网络访问，一般留空。每条 = **主机名 + 备注（可选）**。点「＋ 添加」增行。

#### ③ CIDR 路由

用于 WARP 私有网络访问，一般留空。每条 = **网段 + 备注（可选）**（如 `10.0.0.0/8`）。点「＋ 添加」增行。

> 📌 这三块是**三份彼此独立的数据**，对应三个不同的 Cloudflare 接口。某一块读失败（常见原因是 Token 缺少 **Cloudflare One Networks** 权限）只在那一块显示原因，不影响另外两块。

### 保存后做了什么

| 步骤 | 动作 |
| :--- | :--- |
| **写 ingress** | `PUT /accounts/{账号}/cfd_tunnel/{隧道}/configurations`，同时把该隧道切成云端托管 |
| **补 DNS 路由** | 表单里**新出现**的域名自动 `route dns` 指到这条隧道（**只补不删** —— 免得误删别处在用的 CNAME） |
| **同步主机名 / CIDR 路由** | 与云端做差异比对：新增的建、改过的更新、删掉的移除 |

> ✅ **保存即生效，不用重启隧道**：配置写在 Cloudflare 云端，边缘即时下发；隧道正在运行也不需要停一下再起。

> ⚠️ **要解绑域名请去「DNS 路由绑定」面板**，不要在弹窗里删那一行 —— 面板里的解绑会连带清掉该域名的密码锁（还会顺带清掉云端 ingress 里指向它的规则）；弹窗里的「只补不删」则是为了避免误删别处在用的 CNAME。

## DNS 路由绑定面板

在 **🖥️ 服务端 → 固定隧道 → 「DNS 路由绑定」** 卡片里，按**隧道**分组列出账号下全部已绑定域名。
**每个域名是一个自洽区块，上下两排**：

```
▏mc.example.com                              [改名] [解绑]
▏访问密码锁  已上锁  xxxx.access  cfast_…    [显示凭据] [换密码] [解锁]
```

| 位置 | 元素 | 作用 |
| :--- | :--- | :--- |
| 上排 | **域名本身** | 点击即复制 |
| 上排 | **改名** | 重命名该 DNS 记录（只改这条 CNAME 的名字，指向的隧道不变）。⚠️ 已上锁的域名改名会**删除旧锁**，新域名需重新上锁 |
| 上排 | **解绑** | 删除该 DNS 记录（二次确认），并清掉云端 ingress 里指向它的规则。⚠️ 已上锁的域名解绑会**连带删除它的密码锁** |
| 下排 | **访问密码锁** | 未上锁显示「未上锁 + 上锁」；已上锁显示凭据（默认掩码，点「显示凭据」展开）+ 换密码 / 解锁 |

> 📌 **为什么锁挂在域名下面**：锁是**域名**的属性。早先的三列表格（隧道列 / 域名列 / 密码列）把 32 位的 client id 和 40 位的 secret 塞进固定列宽里既会折行，又跟它保护的域名分处两列看不出对应关系。

> 🗑 **删除隧道会级联清理**：删除确认框会写明「该隧道绑定的 N 个域名与其中的 M 把密码锁会一并删除」，避免云端残留孤儿 Access 应用。

## 访问密码锁（Cloudflare Access）

给固定隧道加一道「密码门」：**上锁后，没有访问凭据的连接一律被 Cloudflare 拒绝（403）** ——
不管对方是浏览器裸开、游戏客户端裸连还是扫描器，统统进不来。
底层用的是 Cloudflare 官方的 **Access + Service Token** 机制，全部云端配置由软件自动完成，不用打开 Cloudflare 后台。

### 服务端：上锁 / 换密码 / 解锁

入口都在 **「DNS 路由绑定」面板里对应的那个域名**上：

| 操作 | 入口 | 效果 |
| :--- | :--- | :--- |
| **上锁** | 域名区块下排的 **「上锁」** | 云端自动创建 Access 应用 + 访问凭据，弹出**访问账号 / 访问密码**供你复制发给对方 |
| **显示凭据** | **「显示凭据 / 隐藏凭据」** | 凭据默认掩码，点一下展开看全（**点凭据本身即复制**，不必展开） |
| **换密码** | **「换密码」**（二次确认） | 旧密码立即作废，正在连接的客户端会被断开 |
| **解锁** | **「解锁」**（二次确认） | 删除云端的 Access 应用与访问凭据，域名恢复公开访问 |

> 📌 **锁加在域名上，不是加在隧道上**：改端口 / 改协议不需要换锁，锁继续有效。
> 一个隧道绑了多个域名时，**每个域名各自独立上锁**，密码互不相同（锁本身就是按域名建的 Access 应用）。

> 📌 上锁前该域名必须先存在（即隧道已绑定该域名）—— 密码锁要有一个保护对象。

> ⚠️ 密码锁保护的是「连接这道门」。若你发布的服务本身有账号体系（比如 MC 服务器的正版验证 / 白名单），那是另一层保护，两者不冲突。

### 客户端：带密码连接

拿到**访问账号 + 访问密码**后：

1. 侧边栏 **💻 客户端** → **「＋ 添加」**，照常填隧道域名与本机监听端口；
2. 填上 **「访问账号」** 与 **「访问密码」**（目标没上锁就留空；两者要么都填、要么都空）；
3. 点行内 **▶**。软件会用这对凭据通过 Cloudflare Access 校验，通过后本地端口即打通；凭据不对或没填，连接会被直接拒绝。

命令行等价写法（不用软件也能连）：

```bash
cloudflared access tcp --hostname mc.example.com --url tcp://127.0.0.1:25566 \
  --service-token-id <访问账号> --service-token-secret <访问密码>
```

### 前提：配置页填一次 Access Token

上锁 / 换密码 / 解锁走的是 Cloudflare Access 管理 API，需要一把有对应**写**权限的 API Token：

- 打开 **⚙️ 配置** 页的 **「Access Token（密码锁凭证）」** 输入框，粘贴 Token 后保存；
- **留空时**软件会用「授权登录」的那把凭证 —— 但它默认**没有** Access 写权限，需要去 Cloudflare 后台补权限（见 [如何获取 Access Token](#如何获取-access-token) 步骤 3）。

> 🔎 实测：`cloudflared tunnel login` 生成的 `cert.pem` 里的 Token **可以读写隧道配置**（所以「编辑云端路由」不需要额外申请 Token），
> 但**对 Access 只有只读权限**（查询 200，创建 / 删除 403）—— 这是上锁功能仍然需要单独 Token 的唯一原因。

## 如何获取 Access Token

1. 登录 [Cloudflare 仪表板](https://dash.cloudflare.com/)，右上角头像 → **我的个人资料（My Profile）** → 左侧 **API 令牌（API Tokens）** → **创建令牌（Create Token）**；
2. 拉到底选 **自定义令牌（Custom token）** → **开始使用**，起个名字（如 `CFTunnel Lock`），权限加两行：

   | 资源 | 权限项 | 级别 |
   | :--- | :--- | :--- |
   | 帐户（Account） | **Access: Apps and Policies** | **编辑（Edit）** |
   | 帐户（Account） | **Access: Service Tokens** | **编辑（Edit）** |

3. **帐户资源（Account Resources）** 选 **包括 → 你的帐户**；一路「继续以显示摘要」→ **创建令牌**；
4. 页面会显示一串 Token（**只显示这一次**），复制它，粘贴进 **⚙️ 配置** 页的 Access Token 输入框保存。

> 💡 **不想新建 Token？** 也可以在 **API 令牌** 列表里找到「Cloudflared 授权登录」生成的那把（名称一般与 `cloudflared` / `Argo Tunnel` 相关），点进去**追加**上面两行 Access 编辑权限 —— 效果一样，软件里留空就能用。

> 🔐 这把 Token 等同于你账号的 Access 管理权限，**不要发给任何人、不要提交到仓库**；它只保存在本机，用于调 Cloudflare API。

## 客户端（访问远程服务）

在异地设备上，通过 Cloudflare 隧道直连已发布的服务。客户端**支持多开**：一条隧道一个独立进程、互不影响，配置持久保存在本机。

1. 侧边栏 **💻 客户端**；
2. 右上角 **「＋ 添加」**：填服务端的**隧道域名**（如 `mc.example.com`）与**本机监听端口**（如 `25566`，**无需与服务端一致**，两端各自独立）；目标开了密码锁就再填**访问账号 / 访问密码**；
3. 每条独占一行，行尾三个按钮：

| 按钮 | 作用 |
| :--- | :--- |
| **▶ / ⏹** | 启动 / 停止**这一条**，按钮随状态切换。停止只断进程、**条目保留**，随时可再点启动 |
| **✎** | 编辑该条配置（运行中时置灰，避免改了配置与进程不一致） |
| **🗑** | 删除该条（二次确认；正在运行会先停掉） |

4. 连接成功后，在本机访问 `127.0.0.1:<本机监听端口>`，即可获得内网般的直连体验；
5. 点 **「刷新」** 与后端对账，控制台会打印「已刷新客户端隧道列表，共获取到 N 条隧道」。

> 📌 标题右侧的状态胶囊显示当前**在连接**的条数（如「已连接 2」），全部断开时显示「未连接」。

## 支持的全部协议

创建隧道时的协议下拉，对应 Cloudflare Tunnel 官方支持的 service 类型：

| 协议 | 用途 | 默认端口 | 说明 |
| :--- | :--- | :--- | :--- |
| **HTTP** | 网站 / 网页服务 | 任意（如 80） | 最常用；`cloudflared` 在边缘解密后再回源 |
| **HTTPS** | 本地已启用 TLS 的服务 | 任意（如 443） | 直连本地 TLS 源站，不二次解密 |
| **TCP** | 任意 TCP 服务 / 游戏服 | 任意 | 最通用的「万能管道」，Minecraft 等游戏服用它 |
| **SSH** | 远程终端 | 22 | 本质是 TCP，端口可改 |
| **RDP** | 远程桌面 | 3389 | 本质是 TCP，端口可改 |
| **SMB** | Windows 文件共享 | 445 | 本质是 TCP，端口可改 |
| **UNIX** | Unix 套接字 | —（填套接字路径） | 仅 Linux / macOS |
| **UNIX+TLS** | Unix 套接字 + TLS | —（填套接字路径） | 仅 Linux / macOS |
| **Hello World** | 内置测试服务器 | —（不显示地址栏） | 验证隧道本身是否打通，零配置 |
| **其他（原始值）** | 存量 / 特殊 service | — | 反解不出协议与端口的云端规则落到这一档，**原样保留不篡改** |
| **未匹配回 404** | 兜底行专有 | —（不显示地址栏） | 只出现在最后那条**兜底行**，且是它的默认档 |

> ⚠️ **关于「默认端口」**：SSH / RDP / SMB 标的 22 / 3389 / 445 只是**默认值**。你的服务监听在哪个端口就填哪个；它们本质都是 TCP 流量，选 TCP 一样通。

> ⚠️ **关于「端口要不要一致」**：服务端填的必须是**本机服务实际监听的端口**；客户端填的是**本机任意空闲端口**，两端**无需一致**，隧道负责映射。

> 💡 **TCP 类服务（MC / SSH / 数据库等）请选 TCP**，不要选 HTTP —— 选错会让客户端连上就断，`cloudflared` 报 `websocket: bad handshake`。

## 数据存放与安全

**界面数据**放在软件自己的目录（即 `cftunnel.exe` 所在目录）：

```
<软件目录>\
├── cftunnel.exe                     主程序
├── uninstall.exe                    卸载器
├── cloudflared.exe                  「安装 / 更新 cloudflared」下载到这里
└── data\
    └── webview\                     WebView2 用户数据：主题 / 端口 / 隧道列表 / 密码锁记录 / 控制台高度
```

**授权凭证不在软件目录里**，交给 cloudflared 自己的默认位置：

```
%USERPROFILE%\.cloudflared\
├── cert.pem                         授权登录证书（账号级，用来管隧道与域名路由）
└── <隧道ID>.json                     隧道密钥
```

- **备份**：两处都要拷 —— 界面数据在 `<软件目录>\data\`，授权凭证在 `%USERPROFILE%\.cloudflared\`。
- **恢复出厂设置**：删掉 `<软件目录>\data\webview\`，下次启动回到默认主题与空列表；登录状态不受影响。
- ✅ **升级 / 卸载都安全**：凭证在用户主目录，覆盖安装也好、卸载器清理安装目录也好，都碰不到它。
  （历史教训：早先版本把凭证放在 `<软件目录>\data\cloudflared`，一次覆盖安装就被卸载器连带清空，授权全丢 —— 所以改回了默认位置。）
- ✅ **和命令行共用同一套凭证**：软件不改写子进程的 `HOME` / `USERPROFILE`，`cloudflared` 写在哪软件就读哪。你在终端里跑 `cloudflared` 和用这个软件，用的是同一份 `~/.cloudflared`。
- ✅ **运行 Token 不落盘**：启动隧道用的 Token 由后端现场换取，只在本机进程间传递，界面不显示、磁盘不保存。

## 常见问题与排错

**Q：点「刷新」报 `解析隧道列表失败: invalid type: null, expected a sequence`？**
A：这是 v1.0.1 之前的旧 bug —— 账号里一条隧道都没有时，`cloudflared tunnel list --output json` 输出的不是 `[]` 而是字面量 `null`，旧代码按数组硬解析就炸了。**已修复**：现在 `null` 会被当成空列表。升级到最新版本即可。

**Q：上锁报 `auth.forbidden` / 403？**
A：Access Token 缺写权限。按[如何获取 Access Token](#如何获取-access-token) 给 Token 加上 `Access: Apps and Policies` 与 `Access: Service Tokens` 的**编辑**权限（改完要点保存）。

**Q：客户端连上就断，日志里是 `websocket: bad handshake`？**
A：隧道那一条 ingress 的 service 协议选错了。TCP 类服务（MC / SSH / RDP / 数据库）必须是 `tcp://`，不能是 `http://`。去「修改隧道」把协议改成 **TCP**，保存即可（云端配置即时生效，不用重启）。

**Q：域名访问 404 / 打不开？**
A：按这个顺序查 —— ① 该域名是否已在「DNS 路由绑定」里出现（没有就去修改隧道里补域名，保存会自动补 DNS 路由）；② 域名对应的 ingress 规则是否在兜底行**之前**（兜底行永远在最后，它之前的规则才有机会命中）；③ DNS 是否已生效（改 DNS 记录通常几十秒内，个别地区看 TTL）。

**Q：改域名后密码锁失效了？**
A：**改名等于删旧锁**（锁绑在域名上，域名换了就是另一个对象）。改名后需要对新域名重新上锁。

**Q：提示 `未找到 cert.pem，请先完成「Cloudflared 授权登录」`？**
A：授权凭证丢了或从未登录。去 **⚙️ 配置** 点一次「🔑 Cloudflared 授权登录」，注意要在浏览器里**选中要授权的域名**。

**Q：我改了协议 / 端口，但连不上，需要重启隧道吗？**
A：不需要。云端配置是运行时生效的，边缘会即时下发；不过正在建立的连接不会自动重连，客户端重新连一次即可。

**Q：删除隧道时提示「该隧道有活动连接」？**
A：软件一律走**强制删除**（`tunnel delete -f`），不会卡在这个提示上；本机在跑的进程会先被停掉。若仍失败，通常是 Token 权限不足，错误原文会打印在控制台。

**Q：隧道多的时候界面会卡吗？**
A：不会。所有会阻塞的网络请求与子进程调用都在后端阻塞线程池里执行，且后端共用一个 HTTP 连接池（同域名连接复用）、互相独立的请求并发发出（例如保存隧道时的多条路由同步）。网络不通时单个请求 8 秒超时，不会把界面锁死。

## 本地开发与编译

### 环境准备

- [Node.js](https://nodejs.org/)（推荐 v20 或 v22 LTS）
- [Rust](https://www.rust-lang.org/)（推荐 1.77+，Tauri 2 要求）
- C++ 编译环境（Windows 为 Visual Studio C++ Build Tools，macOS 为 Xcode Command Line Tools）

### 1. 克隆并安装依赖

```bash
git clone https://github.com/bayueqi/ZQ-CFTunnel.git
cd ZQ-CFTunnel
npm install
```

### 2. 只跑前端（浏览器演示模式）

```bash
npm run dev
```

打开提示的地址即可 —— 非 Tauri 环境下 `src/utils/tauriBridge.ts` 会自动接管所有 IPC 调用，返回内存里的演示数据，**全部交互可点、可走通**（GitHub Pages 上跑的就是这一套）。改界面样式时用这个最快。

### 3. 桌面端开发（含真实后端）

```bash
npm run tauri dev
```

### 4. 本地打包

```bash
npm run tauri build
```

产物在 `src-tauri/target/release/bundle/`。

### 5. 提交前的自检（本地开发用）

> ⚠️ 下面这些脚本放在 `.workbuddy/scripts/`，而该目录被 [.gitignore](.gitignore) 忽略（属于本地开发数据，不随仓库分发）——
> 克隆仓库后不会看到它们，此处仅作职责说明，方便自建同类校验。

只读校验脚本，跑一次不到一秒（本质是「不用编译就能验证结构」）：

```bash
node .workbuddy/scripts/check-i18n.cjs           # 文案键与 types.ts 声明是否双向对齐、占位符是否匹配
node .workbuddy/scripts/check-hardcoded-cjk.cjs  # 界面里是否残留硬编码中文
node .workbuddy/scripts/check-rust-struct.cjs    # Rust：括号配平 / 命令唯一 / 注册表对齐 / run_blocking 成对
node .workbuddy/scripts/check-lock-cleanup.cjs   # 删域名 / 删隧道 / 改名的路径是否都清了密码锁
node .workbuddy/scripts/check-ingress-rows.cjs   # ingress 逐行校验与最终写出结果
```

> `check-sfc.cjs`（真实编译 `App.vue`，并把前端调用 ↔ Rust 命令 ↔ 演示 mock 三方对齐）需要 `@vue/compiler-sfc`，
> 用 `NODE_PATH=<装了该依赖的 node_modules> node .workbuddy/scripts/check-sfc.cjs` 运行；
> `check-i18n-negtest.cjs` 是给上面这些脚本做的反向用例，用来证明它们真的会报错（该红的红、该绿的绿）。
