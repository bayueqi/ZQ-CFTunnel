## 临时链接 vs 固定域名 vs 云端托管

CFTunnel 里的隧道分三种，本质区别在于 **「隧道的配置写在哪、域名怎么来、谁说了算」**：

| 对比维度 | ⚡ 临时链接 | 🟢 固定域名 | 🟣 云端托管 |
| :--- | :--- | :--- | :--- |
| **配置写在哪** | 无配置，纯命令行临时 | 本机，随用随建随改 | Cloudflare 网页后台，一次写死 |
| **域名来源** | Cloudflare 自动分配随机 `xxx.trycloudflare.com` | 绑定你自己的域名（需 `route dns`） | 后台 ingress 写死的自有域名 |
| **是否需授权登录** | ❌ 不需要 | ✅ 需要（授权登录 + 创建隧道） | ✅ 需要（授权登录 + 后台创建隧道） |
| **灵活性** | 最高：填端口即出链接 | ⬆️ 高：协议、端口随时改，改完即生效 | ⬇️ 低：协议/端口在网页端固定，改要回后台 |
| **域名稳定性** | ❌ 每次启动随机变化，停止即失效 | ✅ 固定，可随时重连 | ✅ 固定 |
| **可否多开** | ✅ 可同时生成多条 | ✅ 可同时运行多条命名隧道 | ✅ 可多条并存 |
| **凭证存放** | 无 | 本机 `%USERPROFILE%\.cloudflared\<隧道ID>.json` | 无；运行 Token 每次启动由本机 `cert.pem` 现换，不落盘 |
| **启动命令** | `cloudflared tunnel --url <协议>://127.0.0.1:<端口>` | `cloudflared tunnel --name <名称> --url <协议>://127.0.0.1:<端口>` | `cloudflared tunnel token <隧道>` + `cloudflared tunnel run --token <Token>` |
| **适用场景** | 临时分享个链接、快速测试，不想折腾域名 | 长期发布本地服务，需要固定域名 | 已在后台写好 ingress 规则，只想在本机把它跑起来 |

> 💡 **一句话判断**：只想临时拿个链接给别人看 → 用**临时链接**；要长期固定域名发布本地服务 → 用**固定域名**；已在后台写死配置、只想把它跑起来 → 用**云端托管**。

## 支持的全部协议

软件在「服务端」页提供协议下拉选择，对应 Cloudflare Tunnel 官方支持的 service 类型：

| 协议 | 用途 | 默认端口 | 说明 |
| :--- | :--- | :--- | :--- |
| **HTTP** | 网站 / 网页服务 | 任意（如 80） | 暴露网页，最常用 |
| **HTTPS** | 直连本地 TLS 网站服务 | 任意（如 443） | 本地已启用 HTTPS 时直连，不二次解密 |
| **TCP** | 任意 TCP 服务 / 游戏服 | 任意 | 最通用的"万能管道"，Minecraft 等游戏服用它 |
| **SSH** | 远程终端 | 22 | 本质是 TCP，端口可改 |
| **RDP** | 远程桌面 | 3389 | 本质是 TCP，端口可改 |
| **SMB** | Windows 文件共享 | 445 | 本质是 TCP，端口可改 |
| **UNIX** | Unix 套接字 | —（填套接字路径） | 仅 Linux/macOS |
| **UNIX+TLS** | Unix 套接字 + TLS | —（填套接字路径） | 仅 Linux/macOS |
| **Hello World** | 内置测试服务器 | —（不显示地址栏） | 验证隧道本身是否打通，零配置 |

> ⚠️ **关于"默认端口"**：SSH/RDP/SMB 标注的 22/3389/445 只是**默认值**，你的服务监听在哪个端口，软件里就填哪个端口。它们本质上都是 TCP 流量，选 TCP 一样能通。
>
> ⚠️ **关于"端口是否要一致"**：服务端端口必须 = 本地服务实际监听端口；客户端（本地监听）端口可任填本机空闲端口，两端**无需一致**，隧道会自动做映射。

## 前提条件

使用 CFTunnel 之前，需要先满足以下三项：

1. **一个 Cloudflare 账号**：注册并登录 [dash.cloudflare.com](https://dash.cloudflare.com/)；
2. **一个托管在 Cloudflare 上的域名**：例如 `example.com`，且该域名的 DNS 由 Cloudflare 接管；
3. **cloudflared 已安装并授权登录**：见下一节。

## 安装与授权登录

1. 打开 CFTunnel，在左侧边栏点击 **「⚙️ 配置」**；
2. 点击 **「📦 安装 cloudflared」**：自动检测系统与 CPU 架构，从官方 Release 拉取最新二进制；
3. 点击 **「🔑 Cloudflared 授权登录」**：唤起默认浏览器，在 Cloudflare 网页上**选择你要授权的域名**完成登录，证书保存在 cloudflared 的默认位置 `%USERPROFILE%\.cloudflared\cert.pem`。

> 授权登录这一步，就是把「你的 Cloudflare 账号 + 某个域名」的操控权限下放给本机 cloudflared，之后才能在本机创建隧道、绑定该域名的 DNS 路由。
>
> 📌 授权登录后生成的 `cert.pem` 里带有 API 凭证，CFTunnel 会用它自动查询该域名下已绑定的隧道域名（只读查询 + 你主动点击的改名/解绑操作），不会外传。

## 数据存在哪里

界面数据放在**软件自己的目录**下（即 `cftunnel.exe` 所在目录）：

```
<软件目录>\
├── cftunnel.exe                     主程序
├── uninstall.exe                    卸载器
├── cloudflared.exe                  界面里「安装 / 更新 cloudflared」下载到这里
└── data\
    └── webview\                     WebView2 用户数据：语言 / 主题 / 端口 / 客户端隧道列表
```

**授权凭证不在软件目录里**，而是交给 cloudflared 自己的默认位置：

```
%USERPROFILE%\.cloudflared\
├── cert.pem                         授权登录证书（账号级，用来管隧道和域名路由）
└── <隧道ID>.json                     隧道密钥（本地托管的隧道运行时要读它）
```

- **备份**：两处都要拷 —— 界面数据在 `<软件目录>\data\`，授权凭证在 `%USERPROFILE%\.cloudflared\`。
- **恢复出厂**：删掉 `<软件目录>\data\webview\`，下次启动回到默认语言与空列表，登录状态不受影响。
- ✅ **升级 / 卸载都安全**：凭证在用户主目录里，覆盖安装也好、卸载程序清理安装目录也好，都碰不到它。
  （历史教训：早先版本把凭证塞进 `<软件目录>\data\cloudflared`，一次覆盖安装就被卸载器连带清空，授权全丢 —— 所以改回了默认位置。）
- ✅ **和命令行共用同一套凭证**：软件不改写子进程的 `HOME` / `USERPROFILE`，`cloudflared` 写在哪，软件就读哪。
  你在终端里跑 `cloudflared` 和用这个软件，用的是同一份 `~/.cloudflared`，不会出现「两边凭证不一致」。

## 使用临时链接（免绑定）

临时链接是**最省事**的发布方式：免登录、免凭证、免绑定域名，填个端口点一下，Cloudflare 当场分配一个临时域名。完整流程：

1. 在左侧边栏展开 **「🖥️ 服务端」**，点 **「⚡ 临时链接」**；
2. 选择协议（HTTP / HTTPS / TCP / SSH / RDP / SMB / UNIX / UNIX+TLS / Hello World），填入本地服务端口（选 UNIX / UNIX+TLS 改填套接字路径；选 Hello World 则完全不显示地址栏）；
3. 点 **「生成」**，稍候即可拿到形如 `https://xxx.trycloudflare.com` 的临时域名；
4. 下方 **「隧道列表」** 会列出所有正在运行的临时链接，**点域名即复制**，点「打开」在浏览器中访问；
5. 点 **「停止」** 会先弹二次确认框（显示该隧道协议与临时域名），确认后才真正停止。

> ⚠️ 临时域名**每次启动随机变化、进程停止即失效**，适合临时测试与快速分享。TCP / SSH / RDP 等服务同样可直接通过该临时域名连接（与命名隧道一致）。

## 使用固定域名

固定域名灵活性最高：协议、端口随时在软件里改，改完即启动生效，**且支持多开**（多条命名隧道可同时运行）。

### 基本流程

1. **创建隧道**：在左侧边栏展开 **「🖥️ 服务端 → 固定域名」**，输入隧道名（纯英文字母，如 `mc`），点 **「创建」**；
2. **绑定 DNS 路由**：在下方的 **「DNS 路由绑定」** 填入隧道名 + 域名（如 `mc.example.com`），点 **「绑定」**，让 `mc.example.com` 指向这条隧道；
3. **启动隧道**：选择协议（HTTP / HTTPS / TCP / SSH / RDP / SMB / UNIX / UNIX+TLS / Hello World），填好端口，点 **「启动」**；该按钮在运行时自动变为 **「停止」**，再点一次即停掉这条隧道；
4. **访问**：在浏览器或对应客户端通过 `mc.example.com` 访问你的本地服务。

> 这条隧道的 ingress 规则由软件在启动时按你填的协议/端口即时生成，所以想换端口、换协议，改一下重新启动即可，不用回网页后台。

### 多开与列表操作

隧道列表每行都会显示这条隧道当前是否在运行，多开时一目了然：

| 操作 | 说明 |
| :--- | :--- |
| **状态列** | 绿点「运行中」/ 灰点「未运行」，逐条显示 |
| **行尾 ▶ / ⏹ 按钮** | 单图标按钮，直接启动/停止**这一条**，不用先填名字；按钮自动按状态切换 |
| **双击行** | 把该隧道名填进上方表单，同时带出它上次使用的协议 / 端口 |
| **顶部启动按钮** | 常显，按**表单里那条**隧道判断：未运行显示「启动」，运行中变「停止」，只作用于这一条 |
| **点击域名** | 点每个域名标签即复制到剪贴板 |
| **刷新** | 重新拉取隧道列表，并同步一次真实运行状态（进程意外退出也能对账回来） |
| **删除** | 先点选一行，再点「删除」移除该隧道。走**强制删除**（`tunnel delete -f`）：即使该隧道仍在运行、或云端还有活动连接，也会被直接删掉；本机正在跑的那个进程会先被停掉 |

> 💡 **多开时每条隧道的协议 / 端口从哪来**：隧道对象本身不保存源站协议与端口（Cloudflare 侧只存隧道，ingress 是本地生成的），所以 CFTunnel 会在你每次启动时把「隧道名 → 协议/端口」记到本机。行内 ▶ 按钮据此直接启动；若某条隧道**没有启动记录**，软件只会把它的名字填进表单并提示你确认协议/端口，**绝不会拿别的隧道的端口去硬启动**。

## 管理已绑定域名（改名 / 解绑）

在 **「🖥️ 服务端 → 固定域名 → DNS 路由绑定」** 卡片里，卡片为**左右两栏**：左栏是绑定表单（隧道名 + 域名 + 「绑定」），右栏「**已绑定域名**」按隧道分组列出所有已绑定的域名，每条都可直接管理：

| 按钮 | 作用 |
| :--- | :--- |
| **点域名本身** | 复制该域名 |
| **✎** | 修改绑定域名（**重命名该 DNS 记录**）。弹窗填入新域名，只改动这一条 CNAME 记录的名字，指向的隧道不变 |
| **🗑** | 解除绑定（**删除该 DNS 记录**）。有二次确认弹窗；删除后该域名立即无法访问，**隧道本身和其它域名不受影响** |

> ⚠️ **只改 DNS，不动 ingress**：这两个操作都只操作 Cloudflare 上的 DNS 记录。如果该隧道是**云端托管**且 ingress 里写死了 hostname，那么仅改名 DNS 会导致新域名仍打不通 —— 这类隧道请回 Cloudflare 后台同步修改 ingress 规则。
>
> 📌 该区块只列出**固定域名**的绑定记录，不会碰**云端托管**的配置。

## 使用云端托管

云端托管适合已经在 Cloudflare 后台写死配置、只想在本机把它跑起来的场景：

1. **先完成授权登录**：在 **「⚙️ 配置」** 页点 **「🔑 Cloudflared 授权登录」**。这一步会在本机留下 `cert.pem`，软件靠它自动取 Token —— **不需要你手动复制任何 Token**；
2. **在 Cloudflare 后台创建隧道并写死 ingress 规则**：Zero Trust → Networks → Tunnels，把域名 → 服务的映射写在网页里（后台给出的那串 `cloudflared.exe service install eyJ...` 命令可以无视）；
3. **在软件里点一下就行**：切到 **「🖥️ 服务端 → 云端托管」**，隧道列表里每条隧道后面都有一个 **▶** 按钮，点一下即启动；再点一次（变成 ⏹）即停止；
4. **查看云端配置**：下方「云端配置」按**隧道名称**分组展示它在 Cloudflare 侧的 ingress 规则（匹配域名 → 源站服务），并带上配置的**来源**（云端托管 / 本地托管）与**版本号**；
5. **删除隧道**：列表右上角刷新按钮旁边就是 **「🗑️ 删除」**（作用于列表里选中的那一行），每行行尾也各有一个 🗑 入口。点击都会先弹确认框。

> 🔎 **配置读取走 API，不用先把隧道跑起来**：云端配置通过 Cloudflare REST API 读取（`GET /accounts/{账号}/cfd_tunnel/{隧道}/configurations`），**隧道处于停止状态也能看到规则**，不再依赖解析 cloudflared 的运行日志。凭证直接复用 `cert.pem` 里已有的那串 Token，无需额外申请 API Token。

> 🔐 **Token 不落盘**：启动用的隧道 Token 由后端调用 `cloudflared tunnel token <隧道>` 现场换取，只在本机进程间传递，界面不显示、磁盘不保存。授权凭证只有 `data\cloudflared\cert.pem` 一个。

> 🗑 **删除一律强制**：删除走 `cloudflared tunnel delete -f`，**不管这条隧道是否正在运行、是否还有活动连接**。若这条隧道正好是本机在跑的，软件会先停掉本机进程再删，避免删完还留一个不停重连的僵尸进程。

> 云端托管与固定域名最大的区别：**协议和端口的修改必须回 Cloudflare 网页后台做**，软件只负责"把这条隧道跑起来"和其他基础管理。

## 客户端连接（访问远程服务）

在异地设备上，通过 Cloudflare 隧道直连已发布的服务端。客户端**支持多开**：一条隧道一个独立进程、互不影响，连接配置持久保存在本机。

1. 在左侧边栏点 **「💻 客户端」**；
2. 点右上角 **「+ 添加」**，填服务端绑定的**隧道域名**（如 `mc.example.com`）与**本地监听端口**（可任填本机空闲端口，如 `25566`，无需与服务端一致），点 **「保存」** 即开始连接；
3. 每条隧道独占一行，行尾三个按钮：

| 按钮 | 作用 |
| :--- | :--- |
| **▶ / ⏹** | 启动 / 停止**这一条**，按钮随当前状态自动切换。停止只断进程、**条目保留**，随时可再点启动 |
| **✎** | 编辑该条配置（运行中置灰，避免改了配置与进程不一致） |
| **🗑** | 删除该条（若正在运行会先停掉） |

4. 连接成功后，在本机访问 `127.0.0.1:<本地监听端口>`，即可获得内网般的直连体验；
5. 点 **「刷新」** 与后端对账一次，控制台会打印「已刷新客户端隧道列表，共获取到 N 条隧道」。

> 📌 标题右侧的状态胶囊显示当前**在连接**的条数（如「已连接 2」），全部断开时显示「未连接」。

## 核心特性一览

- 🪟 **Windows 11 Fluent Design 美学**：无边框自定义标题栏、亚克力毛玻璃质感、深色/浅色模式平滑切换。
- 🧭 **可折叠侧边栏导航**：服务端 / 客户端 / 配置 收进左侧边栏，整体可展开折叠（默认折叠为图标栏）；服务端下含「临时链接 / 固定域名 / 云端托管」二级菜单，同样可展开折叠、默认折叠；启动后默认进入配置页。
- ⚡ **临时链接**：免登录、免绑定，填端口即出 `trycloudflare.com` 临时链接，点域名即复制，可一键打开。
- 🔀 **隧道来源智能区分**：自动检测每条隧道的凭证是在本机还是云端，分组展示。
- 🔗 **隧道绑定域名自动展示**：列表直接显示每条隧道绑定的域名（读取 `cert.pem` 自动查询，零配置），点域名即复制。
- ✎ **已绑定域名在线管理**：在「DNS 路由绑定」卡片内按隧道列出全部绑定域名，支持**重命名**与**解除绑定**，带二次确认。
- 🧩 **命名隧道多开**：多条固定域名隧道可同时运行；列表带「状态」列与行内 ▶/⏹ 按钮，可逐条启停；顶部按钮按当前表单那条隧道在「启动 / 停止」间自动切换。
- 🖱️ **双击列表行即填表单**：双击某条隧道，自动填入隧道名并带出它上次使用的协议与端口。
- 🔌 **全协议支持**：HTTP / HTTPS / TCP / SSH / RDP / SMB / UNIX / UNIX+TLS 八大协议 + Hello World 内置测试服务器。
- 🔁 **运行中换协议自动重启**：隧道运行中修改协议/端口，自动停止并重启，相当于即时重置协议。
- 🚫 **单实例运行**：应用禁止多开，重复启动时自动唤起已运行的主窗口。
- ☁️ **云端配置只读展示（API 直读）**：走 Cloudflare REST API 读取 ingress 规则，按**隧道名称**分组，并标出配置来源与版本号；隧道**不启动也能看**，不再依赖解析运行日志。
- 🗑️ **隧道强制删除**：所有类型的隧道删除都带 `--force`，无视「该隧道有活动连接」的拦截；有二次确认弹窗，本机在跑的会先停进程再删。
- 🧳 **便携式数据目录**：界面设置、隧道列表、登录凭证全部集中在软件目录的 `data\` 下，拷走整个文件夹即可完整迁移；cloudflared 的 `HOME` 也被锁在软件目录，`~/.cloudflared` 不会再被自动创建。
- 🌐 **国际化多语言支持**：简体中文、繁體中文、English、Español、Português、日本語 六语言即时切换。
- 📦 **在线一键安装 / 更新 Cloudflared**：自动检测操作系统与 CPU 架构，直连官方 Release。
- 💻 **Windows Terminal 风格集成控制台**：实时捕获守护进程输出，支持划词复制、拖拽调高。
- 📂 **配置文件目录一键直达**：智能打开软件目录下的 `data\cloudflared`，附带凭证防泄露安全告警。
- 🔐 **云端托管零 Token 输入**：不用再手抄 Token，点一下行内 ▶ 就启动；Token 现场换取、不落盘、不上屏。
- 🎵 **Web Audio API 纯代码合成音效**：内置轻快悬浮音、点击音、Tab 切换音与成功音。

## 本地开发与源码编译

### 环境准备
- [Node.js](https://nodejs.org/) (推荐 v20 或 v22 LTS)
- [Rust](https://www.rust-lang.org/) (推荐 1.75+)
- C++ 编译环境 (Windows 为 Visual Studio C++ Build Tools，macOS 为 Xcode Command Line Tools)

### 1. 克隆代码并安装依赖
```bash
git clone https://github.com/bayueqi/ZQ-CFTunnel.git
cd ZQ-CFTunnel
npm install
```

### 2. 启动前端与 Tauri 本地开发
```bash
npm run tauri dev
```

### 3. 本地打包发布版本
```bash
npm run tauri build
```
构建出的安装包与便携版将输出在 `src-tauri/target/release/bundle/` 目录下。

## GitHub Actions 全平台自动化发布

项目内置 [.github/workflows/release.yml](.github/workflows/release.yml) 矩阵构建脚本，推送版本标签即自动并行构建并发布全平台安装包至 GitHub Releases：

```bash
git tag v1.0.1
git push origin v1.0.1
```

> 📌 打标签前记得先把 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json` 里的 `version` 统一改到同一个版本号，否则安装包文件名会和标签对不上。
