## 这是什么

[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/)（`cloudflared`）的桌面客户端，帮你把这些事点完：

- 下载 / 更新 `cloudflared`，走一次浏览器授权登录
- 创建并启动**临时隧道**（随机 `*.trycloudflare.com`）与**固定隧道**（自己的域名）
- 在软件里直接编辑云端的 ingress 路由，不用打开 Cloudflare 后台
- 绑定 / 改名 / 解绑 DNS 记录
- 给域名加一把**访问密码锁**（Cloudflare Access + Service Token），没凭据的连接一律 403
- 在另一台机器上做客户端，把远程服务映射到本机端口

一句话：**本地服务 → 公网可用**，全程不碰命令行、不碰 `config.yml`。

## 快速开始

| 步骤 | 位置 | 做什么 |
| :--- | :--- | :--- |
| 1. 装 cloudflared | **⚙️ 配置** → 「📦 安装 cloudflared」 | 自动识别系统与 CPU 架构，从官方 Release 下载 |
| 2. 授权登录 | **⚙️ 配置** → 「🔑 Cloudflared 授权登录」 | 浏览器里**选中要授权的域名**，证书写入 `%USERPROFILE%\.cloudflared\cert.pem` |
| 3. 建隧道 | **🖥️ 服务端** → 固定 / 临时隧道 → 「＋ 创建」 | 选协议、填本机端口；固定隧道再填域名 |
| 4. 启动 | 列表行尾 **▶** | 临时隧道给你一个 `*.trycloudflare.com`，固定隧道用你绑定的域名 |

> 第 1、2 步只有**固定隧道**需要。临时隧道免登录、免凭证，装上 cloudflared 就能用。

前置条件：一个 Cloudflare 账号；要用固定隧道，再要一个托管在 Cloudflare 上的域名。

## 两种隧道怎么选

| | ⚡ 临时隧道 | 🟢 固定隧道 |
| :--- | :--- | :--- |
| 配置写在哪 | 无配置，命令行临时起 | Cloudflare 云端 ingress（软件里可视化编辑） |
| 域名 | 随机分配的 `xxx.trycloudflare.com` | 你自己域名下的子域名 |
| 需要授权登录 | ❌ | ✅ |
| 域名是否固定 | ❌ 每次启动都变，进程停了就失效 | ✅ 固定，随时可重连 |
| 能否多开 | ✅ | ✅ |
| 能否上密码锁 | ❌ 域名不归你账号 | ✅ 每个域名可单独上锁 |
| 启动命令 | `cloudflared tunnel --url <协议>://127.0.0.1:<端口>` | `cloudflared tunnel run <名称>`（配置取自云端） |
| 适用场景 | 临时分享、验证连通性 | 长期对外发布本地服务 |

固定隧道一旦保存配置就自动成为**云端托管**（`config_src` → `cloudflare`），本机不存 `config.yml`。

## 临时隧道

**🖥️ 服务端 → ⚡ 临时隧道 → 「＋ 创建」** → 选协议 + 填本机端口（UNIX / UNIX+TLS 改填套接字路径，Hello World 不显示地址栏）→ 「生成」→ 稍候拿到 `https://xxx.trycloudflare.com`。

列表每条显示目标地址与临时域名（**点域名即复制**），行尾有 **🌐 打开** / **⏹ 停止**（停止前二次确认）；右上角 **🔄** 与后端对账真实运行状态，状态胶囊显示「运行中 (N)」。

> 临时域名每次启动随机变化、进程停止即失效，只适合临时测试与快速分享。TCP / SSH / RDP 等服务同样可以走临时域名。

## 固定隧道

### 隧道列表

| 列 / 按钮 | 说明 |
| :--- | :--- |
| 隧道 ID / 名称 / 创建时间 | 名称创建时填、**创建后不可改**（它就是凭据文件名） |
| 绑定域名 | 该隧道已绑定的域名，**点域名即复制**；没绑定显示「未绑定」 |
| 连接状态 | Cloudflare 边缘当前的活动连接数，无连接显示 `-` |
| 状态 | 绿点「运行中」/ 灰点「未运行」 |
| 行尾 **▶ / ⏹** | 启动 / 停止**这一条**，按钮随状态自动切换 |
| 行尾 **✎ / 🗑** | 修改（与创建同一弹窗）/ 删除（二次确认；走强制删除，并连带清理该隧道的域名与密码锁） |
| 右上角 **＋ / 🔄** | 新建 / 重新拉取列表并同步运行状态 |
| 状态胶囊 | 显示「运行中 (N)」 |

> 💡 **多开时行内 ▶ 用哪份配置**：隧道对象本身不存源站协议与端口，所以创建 / 修改时软件会把「隧道名 → 协议 / 端口」记在本机，行内 ▶ 据此直接启动。
> 没有记录的隧道点 ▶ 会引导你先点 ✎ 补全，**绝不会拿别的隧道的端口去硬启动**。

### 创建 / 修改隧道

**创建与修改是同一个弹窗** —— 一条固定隧道的内容都在云端 ingress 里，「建一条」和「改一条」填的是同一批东西。差别只有三处：

| | 创建 | 修改 |
| :--- | :--- | :--- |
| 标题 | 「创建固定隧道」 | 「修改隧道」 |
| 隧道名 | 可填写（纯英文字母） | **只读**（改名要连带搬凭据、清旧锁，代价大于收益） |
| 打开时 | 空表单，只有末尾那条兜底行 | 先读回云端已有配置再回填 |

弹窗里的三块，与 Cloudflare 后台的 Tunnel 详情页一一对应。

#### ① 已发布应用程序路由（= 云端 ingress）

一行一条规则，**你只选协议、填端口、填域名，`service` 字符串由程序拼**：

```
[协议 ▾]   [本地端口]   [域名]                  🗑
 HTTP       8080         mc.example.com
```

- **协议**：见下方[支持的全部协议](#支持的全部协议)；
- **本地端口**：选 UNIX / UNIX+TLS 时这格变成**套接字路径**，选 Hello World 时整格隐藏；
- **域名**：这条规则要匹配的 hostname，**可以留空**；
- **其他（原始值）**：反解不出协议与端口的存量规则落到这一档，显示原始 `service` 输入框，**原样保留、不会被改坏**。

点「添加」新增的行是**完全空白**的（协议 http、端口留空），你填哪个就是哪个。

**域名留空 = 这一行不写进云端**。保存时**整行跳过**并记一行日志，不报错、也不影响别的行 ——
Cloudflare 只允许**一条**不带 hostname 的规则，而且必须在最后，那条永远由兜底行担任。

**末尾兜底行（常驻）**：

```
[默认兜底]
 [协议 ▾]  [本地端口]
  未匹配任何域名的请求会走这一条     http_status:404
```

- 它**永远在最后、永远渲染、永远写进云端**，不因为上面的行填成什么样而消失或变形；
- 默认档是 **`http_status:404`**（未匹配就回 404）。把协议换成具体服务再填上端口，未匹配的请求就会**转到那个本地端口**（单域名隧道常用的「反正都给我」写法）；
- 它没有域名输入框、也没有删除按钮 —— 「不带域名」和「排在最后」是它的定义，不是可选项。

**校验规则**（点过保存后才标红）：端口需为 1–65535、域名格式需合法、同一域名不能出现在两条路由里。域名留空的行不参与校验 —— 它本来就不会被写出去。

#### ② 主机名路由 / ③ CIDR 路由

用于 WARP 私有网络访问，一般留空。②每条 = 主机名 + 备注（可选），③每条 = 网段 + 备注（可选，如 `10.0.0.0/8`）。点「添加」增行。

这三块是**三份彼此独立的数据**，对应三个不同的 Cloudflare 接口。某一块读失败（常见原因是 Token 缺少 **Cloudflare One Networks** 权限）只在那一块显示原因，不影响另外两块。

### 保存后做了什么

| 步骤 | 动作 |
| :--- | :--- |
| **写 ingress** | `PUT /accounts/{账号}/cfd_tunnel/{隧道}/configurations`，同时把该隧道切成云端托管 |
| **补 DNS 路由** | 表单里**新出现**的域名自动 `route dns` 指到这条隧道（**只补不删**，免得误删别处在用的 CNAME） |
| **同步主机名 / CIDR 路由** | 与云端做差异比对：新增的建、改过的更新、删掉的移除 |

配置写在云端，边缘即时下发 —— **不用重启隧道**。

> ⚠️ **要解绑域名请去「DNS 路由绑定」面板**，别在弹窗里删那一行：面板里的解绑会连带清掉该域名的密码锁，并清掉云端 ingress 里指向它的规则。

## DNS 路由绑定

在 **🖥️ 服务端 → 固定隧道 → 「DNS 路由绑定」** 卡片里，按**隧道**分组列出账号下全部已绑定域名。每个域名是一个自洽区块，上下两排：

```
▏mc.example.com                              [改名] [解绑]
▏访问密码锁  已上锁  xxxx.access  cfast_…    [显示凭据] [换密码] [解锁]
```

- **点击域名**即复制。
- **改名**：重命名该 DNS 记录（只改这条 CNAME 的名字，指向的隧道不变）。⚠️ 已上锁的域名改名会**删除旧锁**，新域名需重新上锁。
- **解绑**：删除该 DNS 记录（二次确认），并清掉云端 ingress 里指向它的规则。⚠️ 已上锁的域名解绑会**连带删掉它的密码锁**。
- **删除隧道**：确认框会写明「该隧道绑定的 N 个域名与其中的 M 把密码锁会一并删除」，避免云端残留孤儿 Access 应用。

## 访问密码锁（Cloudflare Access）

给固定隧道加一道「密码门」：**上锁后没有凭据的连接一律被 Cloudflare 拒绝（403）** —— 浏览器裸开、游戏客户端裸连、扫描器统统进不来。底层是官方的 **Access + Service Token**，云端配置由软件自动完成。

### 服务端

入口在「DNS 路由绑定」面板里对应的那个域名上：

| 操作 | 效果 |
| :--- | :--- |
| **上锁** | 云端自动创建 Access 应用 + 访问凭据，弹出**访问账号 / 访问密码**供你复制发给对方 |
| **显示凭据** | 凭据默认掩码，点一下展开看全（**点凭据本身即复制**，不必展开） |
| **换密码** | 旧密码立即作废，正在连接的客户端会被断开 |
| **解锁** | 删除云端 Access 应用与凭据，域名恢复公开访问 |

> 📌 锁是**域名**的属性，不是隧道的：改端口、改协议都不用换锁；一个隧道绑了多个域名时**各自独立上锁**，密码互不相同。
> 上锁前该域名必须先存在（即隧道已绑定该域名）—— 密码锁要有一个保护对象。

### 客户端：带密码连接

侧边栏 **💻 客户端 → 「＋ 添加」**，照常填隧道域名与本机监听端口，再填上**访问账号**与**访问密码**（目标没上锁就留空；两者要么都填、要么都空）。点行内 **▶**，凭据通过校验后本地端口即打通。

命令行等价写法（不用软件也能连）：

```bash
cloudflared access tcp --hostname mc.example.com --url tcp://127.0.0.1:25566 \
  --service-token-id <访问账号> --service-token-secret <访问密码>
```

### 上锁需要一把 Access Token

上锁 / 换密码 / 解锁走的是 Cloudflare Access 管理 API，需要一把有**写**权限的 API Token。在 [Cloudflare 仪表板](https://dash.cloudflare.com/) → 右上角头像 → **我的个人资料 → API 令牌 → 创建令牌 → 自定义令牌**，权限加两行：

| 资源 | 权限项 | 级别 |
| :--- | :--- | :--- |
| 帐户（Account） | **Access: Apps and Policies** | **编辑（Edit）** |
| 帐户（Account） | **Access: Service Tokens** | **编辑（Edit）** |

「帐户资源」选 **包括 → 你的帐户** → 创建，页面会显示一串 Token（**只显示这一次**）。复制它，粘进 **⚙️ 配置** 页的 **「Access Token（密码锁凭证）」** 保存。

> 💡 **不想新建 Token？** 也可以给「Cloudflared 授权登录」生成的那把 Token **追加**上面两行权限 —— 效果一样，软件里留空即可。
> 🔎 授权登录的证书本身**能读写隧道配置**（所以编辑云端路由不用额外申请 Token），但**对 Access 只有只读权限**（查询 200，创建 / 删除 403）—— 这就是上锁仍需单独 Token 的唯一原因。
> 🔐 这把 Token 等同于你账号的 Access 管理权限，**不要发给任何人、不要提交到仓库**。

## 客户端

在异地设备上通过隧道直连已发布的服务。**支持多开**：一条隧道一个独立进程、互不影响，配置持久保存在本机。

1. 侧边栏 **💻 客户端** → 右上角 **「＋ 添加」**：填服务端的**隧道域名**（如 `mc.example.com`）与**本机监听端口**（如 `25566`，**无需与服务端一致**，两端各自独立）；目标开了密码锁就再填**访问账号 / 访问密码**；
2. 每条独占一行，行尾三个按钮：

| 按钮 | 作用 |
| :--- | :--- |
| **▶ / ⏹** | 启动 / 停止**这一条**。停止只断进程、**条目保留**，随时可再点启动 |
| **✎** | 编辑该条配置（运行中时置灰，避免改了配置与进程不一致） |
| **🗑** | 删除该条（二次确认；正在运行会先停掉） |

3. 连接成功后，在本机访问 `127.0.0.1:<本机监听端口>` 即可获得内网般的直连体验。

> 标题右侧的胶囊显示当前**在连接**的条数（如「已连接 2」），全部断开时显示「未连接」。

## 支持的全部协议

创建隧道时的协议下拉，对应 Cloudflare Tunnel 官方支持的 service 类型：

| 协议 | 用途 | 说明 |
| :--- | :--- | :--- |
| **HTTP** | 网站 / 网页服务 | 最常用；`cloudflared` 在边缘解密后再回源 |
| **HTTPS** | 本地已启用 TLS 的服务 | 直连本地 TLS 源站，不二次解密 |
| **TCP** | 任意 TCP 服务 / 游戏服 | 最通用的「万能管道」，Minecraft 等游戏服用它 |
| **SSH / RDP / SMB** | 远程终端 / 远程桌面 / Windows 文件共享 | 默认 22 / 3389 / 445，本质都是 TCP，端口随便改 |
| **UNIX / UNIX+TLS** | Unix 套接字 | 填套接字路径，仅 Linux / macOS |
| **Hello World** | 内置测试服务器 | 验证隧道本身是否打通，零配置 |
| **其他（原始值）** | 存量 / 特殊 service | 反解不出协议与端口的云端规则落到这一档，**原样保留不篡改** |
| **未匹配回 404** | 兜底行专有 | 只出现在最后那条兜底行，且是它的默认档 |

> ⚠️ SMB 的 445、SSH 的 22 等只是**默认值**：你的服务监听在哪个端口就填哪个。
> ⚠️ **TCP 类服务（MC / SSH / 数据库等）请选 TCP**，不要选 HTTP —— 选错会让客户端连上就断，`cloudflared` 报 `websocket: bad handshake`。

## 数据存放与安全

**界面数据**在软件自己的目录（`cftunnel.exe` 所在目录）：

```
<软件目录>\
├── cftunnel.exe                     主程序
├── cloudflared.exe                  「安装 / 更新 cloudflared」下载到这里
└── data\
    └── webview\                     WebView2 用户数据：主题 / 端口 / 隧道列表 / 密码锁记录 / 控制台高度
```

**授权凭证不在软件目录里**，交给 cloudflared 自己的默认位置：

```
%USERPROFILE%\.cloudflared\
├── cert.pem                         授权登录证书（账号级，用来管隧道与域名路由）
└── <隧道ID>.json                     隧道密钥
```

- **备份**：两处都要拷 —— `<软件目录>\data\` 与 `%USERPROFILE%\.cloudflared\`。
- **恢复出厂设置**：删掉 `<软件目录>\data\webview\`，下次启动回到默认主题与空列表；登录状态不受影响。
- ✅ 凭证在用户主目录，**升级 / 卸载都碰不到它**（早先版本放在软件目录里，一次覆盖安装就被卸载器连带清空，所以改回了默认位置）。
- ✅ **和命令行共用同一套凭证**：软件不改写子进程的 `HOME` / `USERPROFILE`，终端里跑 `cloudflared` 和用这个软件，用的是同一份 `~/.cloudflared`。
- ✅ **运行 Token 不落盘**：启动隧道用的 Token 由后端现场换取，只在本机进程间传递。

## 本地开发与编译

需要 [Node.js](https://nodejs.org/)（推荐 v20 / v22 LTS）、[Rust](https://www.rust-lang.org/)（推荐 1.77+）、C++ 编译环境（Windows 为 Visual Studio C++ Build Tools，macOS 为 Xcode Command Line Tools）。

```bash
git clone https://github.com/bayueqi/ZQ-CFTunnel.git
cd ZQ-CFTunnel
npm install

npm run dev           # 只跑前端（浏览器演示模式，改界面样式用这个最快）
npm run tauri dev     # 桌面端开发（含真实后端）
npm run tauri build   # 本地打包，产物在 src-tauri/target/release/bundle/
```

非 Tauri 环境下 `src/utils/tauriBridge.ts` 会接管所有 IPC 调用、返回内存里的演示数据，**全部交互可点可走通**（GitHub Pages 上跑的就是这一套）。

> 仓库里带了一组只读自检脚本（放在被 `.gitignore` 忽略的 `.workbuddy/scripts/`，属本地开发数据，克隆仓库看不到）。它们的作用是「不用编译就能验证结构」：文案键与类型声明是否双向对齐、界面里有没有残留硬编码中文、Rust 的括号配平 / 命令注册 / `run_blocking` 是否成对、删域名 / 删隧道 / 改名的路径是否都清了密码锁、ingress 逐行校验与最终写出结果、以及有没有只声明不用的死代码。

## 自动化发布（GitHub Actions）

| 工作流 | 触发条件 | 做什么 |
| :--- | :--- | :--- |
| [release.yml](.github/workflows/release.yml) | 推送 `v*` 标签（或手动触发） | 6 平台矩阵构建并直接发布 Release：Windows x64 / ia32（便携版 / MSI / NSIS）、macOS Intel / Apple Silicon（DMG）、Linux x64 / arm64（AppImage / DEB / RPM） |
| [deploy-pages.yml](.github/workflows/deploy-pages.yml) | 推送 `main` | 编译前端静态包并部署到 GitHub Pages（网页演示模式） |

```bash
git tag v1.0.1
git push origin v1.0.1
```

> 📌 **只推 `main` 不会发 Release**（只会更新网页演示），必须推 `v*` 标签。
> 📌 打标签前把这几处的 `version` 统一到同一个版本号，否则安装包文件名会和标签对不上：`package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json`。
> 📦 **安装包刻意不含 cloudflared** —— 它的体积比整个应用还大，且更新频繁。CI 构建前会主动清掉任何 `binaries` 目录，用户首次使用时在界面里点一次「📦 安装 cloudflared」下载对应平台的官方二进制（`scripts/prepare-sidecars.mjs` 是给需要离线打包的场景预留的可选脚本）。
