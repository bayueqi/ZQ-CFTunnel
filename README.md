## 临时隧道 vs 固定隧道

CFTunnel 里的隧道分两种，本质区别在于 **「配置写在哪、域名怎么来」**：

| 对比维度 | ⚡ 临时隧道 | 🟢 固定隧道 |
| :--- | :--- | :--- |
| **配置写在哪** | 无配置，纯命令行临时 | Cloudflare 云端 ingress（软件里可视化编辑） |
| **域名来源** | Cloudflare 自动分配随机 `xxx.trycloudflare.com` | 绑定你自己的域名 |
| **是否需授权登录** | ❌ 不需要 | ✅ 需要（授权登录 + 创建隧道） |
| **灵活性** | 最高：填端口即出链接 | ⬆️ 高：协议 / 端口 / 域名 / 三块路由随时改，保存即生效 |
| **域名稳定性** | ❌ 每次启动随机变化，停止即失效 | ✅ 固定，可随时重连 |
| **可否多开** | ✅ 可同时生成多条 | ✅ 可同时运行多条 |
| **凭证存放** | 无 | 本机 `%USERPROFILE%\.cloudflared\<隧道ID>.json` |
| **启动命令** | `cloudflared tunnel --url <协议>://127.0.0.1:<端口>` | `cloudflared tunnel run <名称>`（配置取自云端） |
| **适用场景** | 临时分享个链接、快速测试，不想折腾域名 | 长期发布本地服务，需要固定域名 |

> 💡 **一句话判断**：只想临时拿个链接给别人看 → 用**临时隧道**；要长期固定域名发布本地服务 → 用**固定隧道**。

> 📌 **固定隧道创建后即成为「云端托管」**：软件写入云端 ingress 的同时，会把这条隧道的配置源切到 Cloudflare（`config_src` 变为 `cloudflare`）。早期版本里那个单独的「云端托管」视图**已并入固定隧道** —— 一条隧道是不是云端托管只是它的属性，不该让它同时出现在两个列表里。

## 支持的全部协议

软件在创建隧道时提供协议下拉选择，对应 Cloudflare Tunnel 官方支持的 service 类型：

| 协议 | 用途 | 默认端口 | 说明 |
| :--- | :--- | :--- | :--- |
| **HTTP** | 网站 / 网页服务 | 任意（如 80） | 暴露网页，最常用 |
| **HTTPS** | 直连本地 TLS 网站服务 | 任意（如 443） | 本地已启用 HTTPS 时直连，不二次解密 |
| **TCP** | 任意 TCP 服务 / 游戏服 | 任意 | 最通用的"万能管道"，Minecraft 等游戏服用它 |
| **SSH** | 远程终端 | 22 | 本质是 TCP，端口可改 |
| **RDP** | 远程桌面 | 3389 | 本质是 TCP，端口可改 |
| **SMB** | Windows 文件共享 | 445 | 本质是 TCP，端口可改 |
| **UNIX** | Unix 套接字 | —（填套接字路径） | 仅 Linux/macOS |
| **UNIX+TLS** | Unix 套接字 + TLS | —（填套接字路径） | 仅 Linux/macOS |
| **Hello World** | 内置测试服务器 | —（不显示地址栏） | 验证隧道本身是否打通，零配置 |
| **其他（原始值）** | 存量 / 特殊 service | — | 反解不出协议与端口的云端规则会落到这一档，**原样保留不篡改** |
| **未匹配回 404** | 兜底行专有 | —（不显示地址栏） | 只出现在最下面那条**兜底行**且是它的默认档：未匹配任何域名的请求直接回 404 |

> ⚠️ **关于"默认端口"**：SSH/RDP/SMB 标注的 22/3389/445 只是**默认值**，你的服务监听在哪个端口，软件里就填哪个端口。它们本质上都是 TCP 流量，选 TCP 一样能通。

> ⚠️ **关于"端口是否要一致"**：服务端端口必须 = 本地服务实际监听端口；客户端（本地监听）端口可任填本机空闲端口，两端**无需一致**，隧道会自动做映射。

## 前提条件

使用 CFTunnel 之前，需要先满足以下三项：

1. **一个 Cloudflare 账号**：注册并登录 [dash.cloudflare.com](https://dash.cloudflare.com/)；
2. **一个托管在 Cloudflare 上的域名**：例如 `example.com`，且该域名的 DNS 由 Cloudflare 接管；
3. **cloudflared 已安装并授权登录**：见下一节。


---

## 安装与授权登录

1. 打开 CFTunnel，在左侧边栏点击 **「⚙️ 配置」**；
2. 点击 **「📦 安装 cloudflared」**：自动检测系统与 CPU 架构，从官方 Release 拉取最新二进制；
3. 点击 **「🔑 Cloudflared 授权登录」**：唤起默认浏览器，在 Cloudflare 网页上**选择你要授权的域名**完成登录，证书保存在 cloudflared 的默认位置 `%USERPROFILE%\.cloudflared\cert.pem`。

> 授权登录这一步，就是把「你的 Cloudflare 账号 + 某个域名」的操控权限下放给本机 cloudflared，之后才能在本机创建隧道、绑定该域名的 DNS 路由。
>
> 📌 授权登录后生成的 `cert.pem` 里带有 API 凭证，CFTunnel 会用它自动查询该域名下已绑定的隧道域名（只读查询 + 你主动点击的改名 / 解绑 / 编辑云端配置操作）。

## 数据存在哪里

界面数据放在**软件自己的目录**下（即 `cftunnel.exe` 所在目录）：

```
<软件目录>\
├── cftunnel.exe                     主程序
├── uninstall.exe                    卸载器
├── cloudflared.exe                  界面里「安装 / 更新 cloudflared」下载到这里
└── data\
    └── webview\                     WebView2 用户数据：语言 / 主题 / 端口 / 隧道列表 / 密码锁记录
```

**授权凭证不在软件目录里**，而是交给 cloudflared 自己的默认位置：

```
%USERPROFILE%\.cloudflared\
├── cert.pem                         授权登录证书（账号级，用来管隧道和域名路由）
└── <隧道ID>.json                     隧道密钥
```

- **备份**：两处都要拷 —— 界面数据在 `<软件目录>\data\`，授权凭证在 `%USERPROFILE%\.cloudflared\`。
- **恢复出厂**：删掉 `<软件目录>\data\webview\`，下次启动回到默认语言与空列表，登录状态不受影响。
- ✅ **升级 / 卸载都安全**：凭证在用户主目录里，覆盖安装也好、卸载程序清理安装目录也好，都碰不到它。
  （历史教训：早先版本把凭证塞进 `<软件目录>\data\cloudflared`，一次覆盖安装就被卸载器连带清空，授权全丢 —— 所以改回了默认位置。）
- ✅ **和命令行共用同一套凭证**：软件不改写子进程的 `HOME` / `USERPROFILE`，`cloudflared` 写在哪，软件就读哪。
  你在终端里跑 `cloudflared` 和用这个软件，用的是同一份 `~/.cloudflared`，不会出现「两边凭证不一致」。

## 使用临时隧道（免绑定）

临时隧道是**最省事**的发布方式：免登录、免凭证、免绑定域名，填个端口点一下，Cloudflare 当场分配一个临时域名。完整流程：

1. 在左侧边栏展开 **「🖥️ 服务端」**，点 **「⚡ 临时隧道」**；
2. 点列表右上角 **「＋ 创建」**，在弹窗里选择协议（HTTP / HTTPS / TCP / SSH / RDP / SMB / UNIX / UNIX+TLS / Hello World）并填入本地服务端口（选 UNIX / UNIX+TLS 改填套接字路径；选 Hello World 则完全不显示地址栏），点 **「生成」**；
3. 稍候即可拿到形如 `https://xxx.trycloudflare.com` 的临时域名；
4. **「隧道列表」** 会列出所有正在运行的临时隧道，每条显示**目标地址**与**临时域名**（**点域名即复制**），并带 **「🌐 打开」** 与 **「⏹ 停止」** 两个按钮；右上角 **「🔄 刷新」** 同步真实运行状态，状态胶囊显示 **「运行中 (N)」**；
5. 点 **「停止」** 会先弹二次确认框，确认后才真正停止。

> ⚠️ 临时域名**每次启动随机变化、进程停止即失效**，适合临时测试与快速分享。TCP / SSH / RDP 等服务同样可直接通过该临时域名连接（与固定隧道一致）。
>
> ℹ️ 临时域名由 Cloudflare 随机分配、不归你的账号所有，因此**不支持密码锁**；想加密码请用固定隧道。

## 使用固定隧道

固定隧道适合长期发布本地服务：协议、端口、域名都在软件里改，保存即写云端、立即生效，**且支持多开**（多条隧道可同时运行）。

> 📌 **一条固定隧道 = 云端的一组路由**：配置全部住在 Cloudflare 云端 ingress 里，本机不存配置文件。软件会额外在本机记一份「隧道名 → 源站协议 / 端口」的小抄，只为让列表行内的启动按钮不必先打一次网络请求（真正生效的始终是云端配置）。

### 隧道列表

| 列 / 按钮 | 说明 |
| :--- | :--- |
| **隧道 ID** | 隧道唯一标识（鼠标悬停看全，点击该行即选中） |
| **隧道名称** | 创建时填的名字（纯英文字母），创建后不可修改 |
| **创建时间** | Cloudflare 侧记录的创建时间 |
| **绑定域名** | 该隧道已绑定的域名标签，**点域名即复制**；未绑定显示「未绑定」 |
| **连接状态** | Cloudflare 边缘当前的活动连接数，无连接显示 `-` |
| **状态列** | 绿点「运行中」/ 灰点「未运行」，逐条显示 |
| **行尾 ▶ / ⏹** | 直接启动 / 停止**这一条**，按钮随状态自动切换 |
| **行尾 ✎** | 打开**修改**弹窗（与创建是同一个界面，见下一节） |
| **行尾 🗑** | 删除这条隧道（带二次确认）。走**强制删除**（`tunnel delete -f`）：即使仍在运行、云端还有活动连接也会被删掉，本机在跑的进程会先停掉；该隧道绑定的域名与密码锁会一并清理 |
| **右上角 ＋ 创建** | 新建隧道 |
| **右上角 🔄** | 重新拉取隧道列表，并同步一次真实运行状态（进程意外退出也能对账回来） |
| **右上角状态胶囊** | 显示 **「运行中 (N)」**，N 为当前在跑的隧道数 |

> 📌 **列表就是账号下的全部隧道**，不再按「本机有没有凭据文件」拆成两个列表 —— 那个判定跟「是不是云端托管」是两回事，会让同一条隧道出现在两处、或明明云端托管却标成「本地」。

> 💡 **多开时每行的 ▶ 用的是什么配置**：隧道对象本身不保存源站协议与端口（Cloudflare 侧只存隧道），所以 CFTunnel 会在创建 / 修改时把「隧道名 → 协议 / 端口」记到本机。行内 ▶ 据此直接启动；若某条隧道**没有保存记录**，点 ▶ 会引导你先点「修改」补全，**绝不会拿别的隧道的端口去硬启动**。

## 创建 / 修改隧道：三块云端配置

**创建与修改共用同一个弹窗** —— 一条固定隧道的全部内容都住在云端 ingress 里，「创建一条隧道」和「改一条隧道」要填的是同一批东西（协议 / 端口 / 域名），拆成两个界面只会让两边慢慢长歪。两者只有三点差别：

| | 创建 | 修改 |
| :--- | :--- | :--- |
| 标题 | 「创建固定隧道」 | 「修改隧道」 |
| 隧道名 | 可填写（纯英文字母） | **只读**（隧道名就是凭据文件名，改名要连带搬凭据、删旧锁，代价远大于收益） |
| 打开时 | 空白表单 | 先读取云端已有配置并回填 |

弹窗内的三块，与 Cloudflare 后台 Tunnel 详情页一一对应：

### ① 已发布应用程序路由（= 云端 ingress）

一行一条规则，**你只「选协议 + 填端口 + 填域名」，服务地址（`service`）由程序拼**：

```
[协议 ▾]  [本地端口]  [域名（可选）]              🗑
 HTTP     8080        mc.example.com
```

- **协议**：九种服务类型任选（见[支持的全部协议](#支持的全部协议)）；
- **本地端口**：选 UNIX / UNIX+TLS 时这一格变成**套接字路径**，选 Hello World 时整格隐藏；
- **域名**：这条规则要匹配的 hostname，**可以留空** —— 留空的那条会匹配所有 hostname，它自己就成了兜底（见下）；
- **其他（原始值）**：反解不出协议与端口的存量规则会落到这一档，此时该行显示原始 `service` 输入框，**原样保留、不会被软件改坏**。

**域名留空 = 这条自己就是兜底**：它匹配所有 hostname，所以**排在它后面的规则永远轮不到** ——
留空因此只允许出现在**兜底行前面那一行**（排在更前面的位置会标红提示）。这种情况下末尾那条兜底行
会**整行不显示、保存时也不写入**：写进去会让 Cloudflare 判非法（匹配所有 hostname 的规则后面不能再有规则）。
想建一条「不带域名、所有请求都转到本机某个端口」的隧道，就把第一行的域名留空、协议改成 TCP、端口填上即可 ——
不需要先删掉那一行。

**末尾兜底行**：ingress 的最后一条必须不带域名，用来接住所有未匹配的请求。它是一条**能改的真规则**，不是只读提示：

```
[默认兜底]
 [协议 ▾]  [本地端口]
  未匹配任何域名的请求会走这一条  http_status:404
```

- **默认 `http_status:404`**（未匹配就回 404）；把协议换成具体服务再填上端口，未匹配的请求就会**转到那个本地端口**（单域名隧道常用这种「反正都给我」的写法）；
- 它没有域名输入框、也没有删除按钮 —— 「不带域名」和「排在最后」是它的定义，不是可选项；
- 上面某一行的域名被留空时，这条兜底行**整行隐藏**（显示出来也没用：它永远不会被触发）；
- 云端本来就有无域名规则的话则**原样读回**：`http_status:404` 显示为「未匹配回 404」，别的状态码落到「其他（原始值）」原文保留。

**校验**（不通过会在对应行下方标红）：端口需为 1–65535、域名格式需合法、**留空域名的行只能排在兜底行前面**（排更前面会让它后面的规则永远轮不到）、同一域名只能出现在一条路由里。

### ② 主机名路由

用于 WARP 私有网络访问，一般留空。每条 = **主机名 + 备注（可选）**。点「＋ 添加」增行。

### ③ CIDR 路由

用于 WARP 私有网络访问，一般留空。每条 = **网段 + 备注（可选）**（如 `10.0.0.0/8`）。点「＋ 添加」增行。

### 保存后做了什么

| 步骤 | 动作 |
| :--- | :--- |
| **写 ingress** | `PUT /accounts/{账号}/cfd_tunnel/{隧道}/configurations`，同时把该隧道的配置源切到 Cloudflare |
| **补 DNS 路由** | 表单里**新出现**的域名会自动 `route dns` 指到这条隧道（**只补不删** —— 删域名不会连带删 DNS 记录，免得误删别处在用的 CNAME） |
| **同步主机名 / CIDR 路由** | 与云端做差异比对：新增的建、改过的更新、删掉的移除 |

> ✅ **保存即生效，不用重启隧道**：配置写在 Cloudflare 云端，边缘即时下发；即便该隧道正在运行也不需要停一下再起。

> ⚠️ **要解绑域名请去「DNS 路由绑定」面板**，而不是在弹窗里删掉那一行 —— 面板里的解绑会连带清掉该域名的密码锁，弹窗里的「只补不删」则是为了避免误删别处在用的 CNAME 记录。

## 管理已绑定域名与访问密码锁

在 **「🖥️ 服务端 → 固定隧道 → DNS 路由绑定」** 卡片里，按**隧道**分组列出该账号下全部已绑定域名，**每个域名是一个自洽区块**，上下两排：

```
▏mc.example.com                          [改名] [解绑]
▏访问密码锁  已上锁  xxxx.access  cfast_…  [显示凭据] [换密码] [解锁]
```

| 位置 | 元素 | 作用 |
| :--- | :--- | :--- |
| 上排 | **域名本身** | 点击即复制 |
| 上排 | **改名** | 重命名该 DNS 记录（只改这一条 CNAME 的名字，指向的隧道不变）。⚠️ 已上锁的域名改名会**删除旧锁**，新域名需重新上锁 |
| 上排 | **解绑** | 删除该 DNS 记录（二次确认）。⚠️ 已上锁的域名解绑会**连带删除它的密码锁**，访问账号与密码立即失效 |
| 下排 | **访问密码锁** | 未上锁显示「未上锁 + 上锁」；已上锁显示凭据（默认掩码，点「显示凭据」展开）+ 换密码 / 解锁 |

> 📌 **为什么锁放在域名下面**：锁是**域名**的属性。早先的三列表格（隧道列 / 域名列 / 密码列）把 32 位的 client id 和 40 位的 secret 塞进固定列宽里既会折行，又跟它保护的域名分处两列看不出对应关系 —— 所以改成了现在这种「域名聚合区块」。

> 📌 **重命名 / 解绑只动 DNS 记录**。要改 ingress 里写的域名，请在 **✎ 修改**弹窗里改（软件会把改动写进云端配置，见上一节）。

> 🗑 **删除隧道会级联清理**：删除确认框会写明「该隧道绑定的 N 个域名与其中的 M 把密码锁会一并删除」，避免云端残留孤儿 Access 应用。

## 隧道密码锁（Cloudflare Access）

给固定隧道加一道「密码门」：**上锁后，没有访问密码的连接一律被 Cloudflare 拒绝（403）**——不管对方是浏览器裸开、游戏客户端裸连还是扫描器，统统进不来。底层用的是 Cloudflare 官方的 **Cloudflare Access + Service Token** 机制，由软件自动完成全部云端配置，全程不用打开 Cloudflare 后台。

### 服务端：上锁 / 解锁 / 换密码

入口都在 **「DNS 路由绑定」面板里对应的那个域名**上：

| 操作 | 入口 | 效果 |
| :--- | :--- | :--- |
| **上锁** | 域名区块下排的 **「上锁」** | 云端自动创建 Access 应用 + 访问凭据，弹出**访问账号 / 访问密码**供你复制发给对方；之后该域名区块显示凭据 |
| **显示凭据** | **「显示凭据 / 隐藏凭据」** | 凭据默认掩码显示，点一下展开看全（**点凭据本身即复制**，无需展开） |
| **换密码** | **「换密码」**（带二次确认） | 旧的访问密码立即作废，正在连接的客户端会被断开 |
| **解锁** | **「解锁」**（带二次确认） | 删除云端的 Access 应用与访问凭据，域名恢复公开访问 |

> 📌 **密码锁加在域名上，不是加在隧道上**：改端口 / 改协议不需要换锁，锁继续有效。一个隧道绑了多个域名时，**每个域名各自独立上锁**，密码各不相同（锁本身就是按域名在 Cloudflare 上建的 Access 应用）。
>
> 📌 上锁前该域名必须先存在（即隧道已绑定该域名），密码锁要有一个保护对象。
>
> ⚠️ 密码锁保护的是「连接这道门」。若你发布的服务本身有账号体系（比如 MC 服务器的正版验证 / 白名单），那是另一层保护，两者不冲突。

### 客户端：带密码连接

对方拿到你发的**访问账号 + 访问密码**后，在 CFTunnel 客户端里：

1. 点 **「＋ 添加」**，照常填隧道域名与本地监听端口；
2. 填上 **「访问账号」** 与 **「访问密码」**（目标隧道没上锁就留空，两者要么都填、要么都空）；
3. 点行内 **▶** 连接。软件会用这对凭据通过 Cloudflare Access 校验，通过后本地端口即打通；凭据不对或没填，连接会被直接拒绝。

命令行等价写法（不用软件也能连）：

```bash
cloudflared access tcp --hostname mc.example.com --url tcp://127.0.0.1:25566 \
  --service-token-id <访问账号> --service-token-secret <访问密码>
```

### 前提：配置页填一次 Access Token

上锁 / 解锁 / 换密码走的是 Cloudflare Access 管理 API，需要一把有对应写权限的 API Token：

- 打开软件 **「⚙️ 配置」** 页顶部 **「Access Token（密码锁凭证）」** 输入框，粘贴你的 Token（获取方法见下一节），点保存；
- **留空时**软件会改用「授权登录」的凭证 —— 但那把凭证默认**没有** Access 写权限，需要在 Cloudflare 后台给它补上权限（和上一条是同一件事，见下一节步骤 3 的说明）。

> 🔎 实测：`cloudflared tunnel login` 生成的 `cert.pem` 里的 Token **可以读写隧道配置**（所以「编辑三块云端路由」不需要额外申请 Token），但**对 Access 只有只读权限**（查询 200、创建 / 删除 403）—— 这是上锁功能仍需要单独 Token 的唯一原因。

## 如何获取 Access Token

1. 登录 [Cloudflare 仪表板](https://dash.cloudflare.com/)，右上角头像 → **我的个人资料（My Profile）** → 左侧 **API 令牌（API Tokens）** → **创建令牌（Create Token）**；
2. 拉到底选 **自定义令牌（Custom token）** → **开始使用**，起个名字（如 `CFTunnel Lock`），权限按下表添加两行：

   | 资源 | 权限项 | 级别 |
   | :--- | :--- | :--- |
   | 帐户（Account） | **Access: Apps and Policies** | **编辑（Edit）** |
   | 帐户（Account） | **Access: Service Tokens** | **编辑（Edit）** |

3. **帐户资源（Account Resources）** 选 **包括 → 你的帐户**；一路 **继续以显示摘要** → **创建令牌**；
4. 页面会显示一串 Token（**只显示这一次**），复制它，粘贴进 CFTunnel **「⚙️ 配置」页的 Access Token 输入框**保存即可。

> 💡 **不想新建 Token？** 也可以在同一个 **API 令牌** 列表页里找到「Cloudflared 授权登录」生成的那把 Token（名称一般为 `cloudflared` / `Argo Tunnel` 相关），点进去给它**追加**上面两行 Access 编辑权限 —— 效果一样，软件里留空就能用。
>
> 🔐 这把 Token 等同于你 Cloudflare 账号的 Access 管理权限，**不要发给任何人、不要提交到代码仓库**；它只保存在本机软件配置里，用于调 Cloudflare API。

## 客户端连接（访问远程服务）

在异地设备上，通过 Cloudflare 隧道直连已发布的服务端。客户端**支持多开**：一条隧道一个独立进程、互不影响，连接配置持久保存在本机。

1. 在左侧边栏点 **「💻 客户端」**；
2. 点右上角 **「＋ 添加」**，填服务端绑定的**隧道域名**（如 `mc.example.com`）与**本地监听端口**（可任填本机空闲端口，如 `25566`，无需与服务端一致）；若目标隧道开了**密码锁**，再填上服务端发给你的**访问账号 / 访问密码**（没上锁就留空），点 **「保存」**；
3. 每条隧道独占一行，行尾三个按钮：

| 按钮 | 作用 |
| :--- | :--- |
| **▶ / ⏹** | 启动 / 停止**这一条**，按钮随当前状态自动切换。停止只断进程、**条目保留**，随时可再点启动 |
| **✎** | 编辑该条配置（含访问账号 / 访问密码；运行中置灰，避免改了配置与进程不一致） |
| **🗑** | 删除该条（带二次确认；若正在运行会先停掉） |

4. 「访问密码」列明文显示已保存的凭据（点击复制），没配则显示「—」；
5. 连接成功后，在本机访问 `127.0.0.1:<本地监听端口>`，即可获得内网般的直连体验；
6. 点 **「刷新」** 与后端对账一次，控制台会打印「已刷新客户端隧道列表，共获取到 N 条隧道」。

> 📌 标题右侧的状态胶囊显示当前**在连接**的条数（如「已连接 2」），全部断开时显示「未连接」。

## 核心特性一览

- 🪟 **Windows 11 Fluent Design 美学**：无边框自定义标题栏、亚克力毛玻璃质感、深色/浅色模式平滑切换。
- 🧭 **可折叠侧边栏导航**：服务端 / 客户端 / 配置 收进左侧边栏，整体可展开折叠（默认折叠为图标栏）；服务端下含「临时隧道 / 固定隧道」二级菜单，同样可展开折叠、默认折叠；启动后默认进入配置页。
- ⚡ **临时隧道**：免登录、免绑定，填端口即出 `trycloudflare.com` 临时域名，点域名即复制，可一键在浏览器打开。
- 🎛️ **云端配置可视化编辑**：固定隧道的三块云端路由（**已发布应用程序路由 / 主机名路由 / CIDR 路由**）全部可以在软件里增删改 —— 协议用下拉选、端口用输入框填，`service` 字符串由程序拼装，**不用手写也读不出错**；保存即写云端并立即生效。
- 🧩 **创建与修改同一界面**：固定隧道的创建 / 修改共用一个弹窗，改一条隧道和建一条隧道是同一套操作；修改态会先读回云端已有配置填进表单，不认识的规则原样保留（其他 → 原始值）。
- 🔀 **固定隧道多开**：多条隧道可同时运行；列表带「状态」列与行内 ▶/⏹ 按钮，可逐条启停。
- 🔗 **绑定域名一目了然**：列表的「绑定域名」列直接显示每条隧道绑定的域名（读 `cert.pem` 自动查询，零配置），点域名即复制。
- ✎ **域名与密码锁在线管理**：在「DNS 路由绑定」卡片内按隧道分组列出全部绑定域名，支持**改名**、**解绑**，以及**逐域名的访问密码锁**（上锁 / 换密码 / 解锁），全部带二次确认。
- 🔐 **隧道密码锁（Cloudflare Access）**：每个域名可独立上锁 —— 上锁后没有「访问账号 / 访问密码」的连接一律被 Cloudflare 403 拒绝（浏览器裸开、游戏客户端裸连都进不来）；凭据明文展示、点击复制；客户端填入同一对凭据即可带密码连接。服务端创建 / 客户端连接全程在软件里点两下，不用开 Cloudflare 后台。
- 🔌 **全协议支持**：HTTP / HTTPS / TCP / SSH / RDP / SMB / UNIX / UNIX+TLS + Hello World 内置测试服务器 + 「其他（原始值）」兜底。
- 🚫 **单实例运行**：应用禁止多开，重复启动时自动唤起已运行的主窗口。
- 🗑️ **隧道强制删除 + 级联清理**：所有删除都带 `--force`，无视「该隧道有活动连接」的拦截；删除一条隧道会连带清理它绑定的域名与密码锁，避免云端残留孤儿 Access 应用；有二次确认弹窗，本机在跑的会先停进程再删。
- 🧳 **数据分两处、各归其位**：界面设置 / 隧道列表在软件目录的 `data\webview\`（拷走即可迁移界面配置），登录凭证 `cert.pem` 与隧道密钥 `<隧道ID>.json` 放在 cloudflared 默认的 `%USERPROFILE%\.cloudflared\` —— 跟命令行共用同一套，重装软件也不会被清掉。
- 🌐 **国际化多语言支持**：简体中文、繁體中文、English、Español、Português、日本語 六语言即时切换。
- 📦 **在线一键安装 / 更新 Cloudflared**：自动检测操作系统与 CPU 架构，直连官方 Release。
- 💻 **Windows Terminal 风格集成控制台**：实时捕获守护进程输出，支持划词复制、拖拽调高。
- 📂 **配置文件目录一键直达**：智能打开 cloudflared 的凭证目录 `%USERPROFILE%\.cloudflared`，附带凭证防泄露安全告警。
- 🔐 **运行 Token 不落盘**：启动用的隧道 Token 由后端现场换取，只在本机进程间传递，界面不显示、磁盘不保存。
- 🎵 **Web Audio API 纯代码合成音效**：内置轻快悬浮音、点击音、Tab 切换音与成功音。

## 本地开发与源码编译

### 环境准备
- [Node.js](https://nodejs.org/) (推荐 v20 或 v22 LTS)
- [Rust](https://www.rust-lang.org/) (推荐 1.75+)
- C++ 编译环境 (Windows 为 Visual Studio C++ Build Tools，macOS 为 Xcode Command Line Tools)

### 1. 克隆代码并安装依赖
```bash
git clone https://github.com/bayueqi/ZQ-CFTunnel.git
cd ZQ-CFTunnel
npm install
```

### 2. 启动前端与 Tauri 本地开发
```bash
npm run tauri dev
```

### 3. 本地打包发布版本
```bash
npm run tauri build
```
构建出的安装包与便携版将输出在 `src-tauri/target/release/bundle/` 目录下。
